# 修改记录详细模板参考

> 本文件是 `docs/修改记录/TEMPLATE.md` 的扩展说明，提供各章节的编写细则。

## 修改概述

简明扼要，1-3 句话，说明：
- 改了**什么**（功能/组件/配置）
- 为什么改（BUG/需求/优化）
- 涉及范围（前端/后端/数据库）

## 修改详情

### 每个修改点包含

| 要素 | 说明 | 示例 |
|------|------|------|
| 位置 | 文件路径 + 行号 | `OrderController.java:56` |
| 修改前 | 原始代码（前后各 3 行上下文） | — |
| 修改后 | 修改后代码（前后各 3 行上下文） | — |
| 原因 | 为何这样修改 | "修复空指针异常" |

### 上下文要求

- 上下文前后各 3 行
- 修改行用 `+`/`-` 标记（如 diff）
- 新增文件标注"新建"，删除文件标注"删除"

## 回滚方案

### 不依赖 git

回滚方法必须是**手动替换代码**，不能写 `git revert` / `git checkout`。

### 每种操作的回滚方法

| 操作 | 回滚方法 |
|------|---------|
| 修改 | 打开文件，定位行号，还原为修改前内容 |
| 新增 | 删除该文件 |
| 删除 | 重新创建文件，粘贴删除前内容 |
| 数据库 | 执行反向迁移 SQL |

## 文件清单

格式：`| {路径} | {修改/新增/删除} | {说明} |`

路径使用相对于项目根目录的路径。

## 验证变更日志

当存在 Phase 6 之后的验证→回退→修复循环时，在修改记录末尾追加：

```markdown
## 验证变更日志
| 轮次 | 发现 | 修复 | 回退阶段 |
|------|------|------|---------|
| 1 | {描述} | {修复摘要} | Phase 5 |
```

- 轮次从 1 开始递增
- 发现 = 验证时发现的问题
- 修复 = 回退后修复的摘要
- 回退阶段 = 回退到的 Phase 编号
