# 决定不做清单（Out-of-Scope Registry）

> 以下操作不在 fullstack-flow 流程范围内。Agent 在任何 Phase 都不应执行这些操作。
> 此清单与 Phase 3 规格文档中的 Scope 边界共同构成完整的不做范围定义。

## 数据操作

| 禁止操作 | 说明 | 替代方式 |
|---------|------|---------|
| 直接修改数据库 schema | 表结构变更需 DBA 审核 | 记录到修改记录，标注"需 DBA 执行" |
| 直接 SQL INSERT/UPDATE/DELETE | 不直接写数据库 | 通过 API 调用链创建/修改数据 |
| 执行 DROP TABLE / TRUNCATE | 危险操作，禁止 | 不执行 |
| 修改生产数据库配置 | 无权限 | 不执行 |

## 部署运维

| 禁止操作 | 说明 |
|---------|------|
| 部署到生产环境 | 由 CI/CD pipeline 负责 |
| 修改服务器配置（Nginx/Tomcat 等） | 由运维团队负责 |
| 操作 Docker/容器编排 | 不在流程范围内 |
| 修改 CI/CD pipeline 配置 | 由 DevOps 团队负责 |

## 测试

| 禁止操作 | 说明 |
|---------|------|
| 编写纯单元测试（无 API 调用） | 单元测试由开发者负责，本流程只做 API 层测试 |
| 运行耗时 > 5 分钟的测试 | 超长测试应拆分为独立任务 |
| 直接访问生产数据库进行测试 | 仅使用开发/测试数据库 |
| 执行破坏性测试（如删除生产数据） | 仅验证正常/异常流程 |

## 代码修改

| 禁止操作 | 说明 |
|---------|------|
| 修改非本次 Scope 的文件 | 严格按规格文档的 Scope 执行 |
| 引入计划外的新依赖 | 新增依赖必须先在规格/计划阶段评估 |
| 修改 package.json / pom.xml 以外的构建配置 | 构建配置变更需独立评估 |
| 修改 API 响应格式（未在 Scope 中声明） | 向后兼容原则，响应格式变更需规格阶段确认 |
| 执行全局搜索替换 | 精确修改，避免意外影响 |

## 流程操作

| 禁止操作 | 说明 |
|---------|------|
| 跳过质量门控 | 所有门控不可跳过 |
| 在 Phase 3/4 中写代码 | 只读模式 |
| 修改 state.yaml 以外的 `.codebuddy/workflow/` 文件 | state.yaml 仅通过入口/出口协议自动更新 |
| 删除或修改历史制品（探路报告/规格文档等） | 只追加不覆盖 |
| 在 Phase 1/2/3/4 中直接修改代码 | 代码修改仅在 Phase 5 进行 |

## 违反处理

发现 Agent 越界操作时：

1. 立即停止当前操作
2. 记录越界行为到修改记录
3. 评估影响范围
4. 如有必要，回退到对应 Phase 重新执行
