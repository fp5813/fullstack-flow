## 逐项详情

### ① 复盘机制（已完成）

- Phase 6.7 定义完整的六步流程（Step 0→6）
- 混合触发模式：轻量"复盘四问" + 强制触发条件（BUG/重构/重复BUG/用户要求）
- 五维分析框架：流程缺陷 / 代码质量 / 项目惯例 / 技能可用性 / 根因（5 Why）
- 5 种沉淀类型 A-E：直接对应 SKILL.md 规则 / Phase 检查项 / references / Memory / Phase 文档
- 强制执行规则 22-24, 28, 37

### ② 定期回顾 Skill 使用情况（缺失）

**当前状态**：纯事件驱动——仅"每次开发工作流执行后"按四问判定是否复盘。
**无以下能力**：
- 无月度/季度定时健康度检查
- 无跨项目/跨时间的使用情况聚合分析
- 无 Skill 自身过时规则/冲突规则检测
- 无执行次数计数器（N 次后自动触发综合回顾）

### ③ 失败案例/新坑补充（部分实现）

**已实现**：
| 沉淀渠道 | 捕获内容 | 落地位置 |
|---------|---------|---------|
| 复盘 A-E 类型 | 流程缺陷→新规则、检查遗漏、代码模式、项目惯例、技能缺陷 | SKILL.md 等 |
| 验证变更日志 | 发现→修复→回退历程 | 修改记录 |
| Instinct 提取 | 可复用正模式 | `.codebuddy/instincts/` |

**缺失**：
- 无独立的失败案例库（`docs/失败案例/`）
- 失败案例缺乏标准化模板（问题→根因→修复→预防）
- 无 `/failure-cases` 检索命令

### ④ 进化知识库（已完成）

- Instinct 完整生命周期：提取 → 存储 → 置信度积累 → Promotion → 进化
- 7 类领域分类：代码/数据/测试/安全/UX/流程/领域
- 置信度体系：首 0.60 → 复现 +0.05~0.10 → 确认 +0.15 → 阈值 0.80 → 全局
- Memory 同步 + CHANGELOG 版本管理

## 改进建议（按优先级）

### 高优先: 建立"定期 Skill 健康度检查"机制

- 新增 `/skill-health-check` 命令
- 建立月度回顾制度（每 30 天 或 每 10 次执行触发）
- 输出 `docs/技能审计/健康度报告-YYYY-MM.md`

### 中优先: 建立"失败案例库"

- retrospect.md 新增 Step 2.3 "失败案例结构化"
- 创建 `docs/失败案例/` 目录 + 标准模板 + FAILURE-INDEX.md
- 新增沉淀类型 F（失败案例）
- 新增 `/failure-cases` 检索命令

### 中优先: 新增"汇总复盘"机制

- retrospect.md 新增 Step 5 "汇总检查"
- 每次复盘后检查最近 3 次记录，发现重复模式自动触发增强沉淀
- proccess_improvements.yaml 扩展 `retrospect` 来源
